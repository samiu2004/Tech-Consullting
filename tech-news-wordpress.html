WordPress flaw lets attackers run code during updates

The most dangerous moment for a WordPress site is not when it is running. It is when it is updating.

By TechConsulting Editorial Published 3 November 2026 Sources checked 13 November 2026 2 min read

The most dangerous moment for a WordPress site is not when it is running. It is when it is updating.

A race condition in the way WordPress applies core updates, CVE-2026-119977, lets an attacker with no login at all run code during the upgrade window. The attacker reaches a predictable staging folder while the site is updating. It affects WordPress 4.7 to 7.1.3. WordPress fixed the flaw on 28 October, and CISA added it to its catalogue on 3 November, with a federal deadline of 6 November.

Attackers moved fast. Wordfence counted more than 18,500 probes of the staging paths in the first 21 hours. Those were attempts, not compromises, but Wordfence reports it is blocking thousands of attempts a day. The lesson is blunt. Twice in one week, the maintenance path was the attack path, and a patch that exists is not the same as a patch that is installed.

Why it matters to you: if your site, or a site you pay someone to run, uses WordPress, the risk window is the update itself. An attacker needs no password and no account. They only need to arrive at the right second, while files are landing in a folder whose address they can guess.

What to do now

  • Update to WordPress 7.1.4, or the fixed release for your branch, for example 7.0.8, 6.9.11, or 6.8.12.
  • Block public web access to the wp-content/upgrade folder.
  • Do not leave upgrades half done. Finish the update, then check the site still works.
  • If someone else manages your site, ask them today which WordPress version you are on.
